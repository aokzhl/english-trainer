# WordForge — тренажёр английских слов
## Документ требований (v1.4 — утверждено)

## 1. Цель и аудитория

**Цель:** помочь пользователю системно расширять словарный запас на любом
уровне (A1–C2) через ежедневные короткие тренировки (3–5 минут).
Стартовая точка пользователя — ~A2, но контент и механика покрывают все уровни.

**Пользователь:** русскоязычный, изучает английский самостоятельно, уровень A2.
Основная боль — слова плохо запоминаются и быстро забываются.

**Ключевая метрика успеха:** пользователь возвращается ежедневно и стабильно
переводит слова из статуса «новое» в статус «выучено».

## 2. Контент

### 2.1. Типы карточек (три колоды)
1. **Слова** — лексика всех уровней A1–C2
2. **Фразовые глаголы** — от базовых до продвинутых
3. **Идиомы** — распространённые разговорные

Встроенный контент хранится в базе как общий (seed), доступен всем пользователям.
Стартовый объём: ~150+ слов, ~50 фразовых глаголов, ~35 идиом с разметкой по
уровням; словарь пополняется без изменения кода (добавлением seed-данных).

### 2.2. Структура карточки
- Слово/фраза на английском
- Перевод на русский
- **Уровень CEFR:** A1 / A2 / B1 / B2 / C1 / C2
- **Тематическая категория:** еда, путешествия, работа, эмоции, быт, общение и т.д.
- Пример употребления (английское предложение)
- **Синонимы** (если есть)
- **Антонимы** (если есть)
- Колода (words / phrasal / idioms)
- Озвучка произношения — кнопка 🔊 (Web Speech API, голос en-US/en-GB)

### 2.3. Экран «Словарь» (отдельный раздел, не только карточки)
Полный список всех слов в виде каталога:
- **Группировка/фильтры:** по уровню (A1–C2), по категории, по колоде,
  по статусу изучения (новые / в процессе / выученные / скрытые)
- **Сортировки:** по алфавиту (A→Z, Z→A), по уровню, по прогрессу изучения,
  по дате добавления
- **Поиск** по английскому слову и русскому переводу
- Каждая строка раскрывается: перевод, пример, синонимы, антонимы, озвучка,
  индикатор SRS-прогресса
- Из словаря слово можно скрыть из тренировок или отправить учиться

### 2.4. Пользовательский контент
- Пользователь добавляет свои карточки в любую колоду с указанием уровня,
  категории, примера, синонимов и антонимов (обязательны только слово и перевод)
- Свои карточки можно редактировать и удалять; встроенные — скрывать

## 3. Механика обучения

### 3.1. Интервальное повторение (система Лейтнера)
- У каждой пары «пользователь + карточка» есть уровень 0–6 и дата следующего показа
- «Знаю» → уровень +1, интервалы: сразу → 1 → 2 → 4 → 7 → 15 → 30 дней
- «Не знаю» → уровень сбрасывается на 0
- Уровень 6 = «выучено»
- Если карточек «к повторению» меньше размера сессии — подмешиваются новые

### 3.2. Режимы тренировки (все три в MVP)
1. **Карточки** — EN-слово → вспомнил → перевернул → «знаю / не знаю»
2. **Викторина** — правильный перевод из 4 вариантов, направления EN→RU и RU→EN чередуются
3. **Письмо** — по переводу напечатать слово (без учёта регистра; при ошибке показывается правильный ответ)

Во всех режимах результат ответа обновляет SRS-уровень карточки.

### 3.3. Сессия
- ~15 карточек за сессию, прогресс-бар
- Перед стартом можно ограничить сессию: колода + уровень (напр. «только A2»)
  + категория (напр. «путешествия»)
- Экран результатов: «знаю» / «повторить», обновление стрика

## 4. Аккаунты и прогресс

- Регистрация и вход: **email + пароль** (пароль хешируется bcrypt, сессия — JWT)
- Прогресс, свои слова и стрик привязаны к аккаунту → доступны с любого устройства
- **Стрик** 🔥 — дни занятий подряд; счётчики «к повторению сегодня», «выучено всего»
- Прогресс по каждой колоде отдельно

## 5. Архитектура и стек (утверждено)

| Слой | Технология |
|------|-----------|
| Монорепозиторий | **pnpm workspaces + Turborepo** (apps/client, apps/server, packages/shared) |
| Frontend | React 18 + Vite + TypeScript |
| Архитектура фронтенда | FEOD (Fractal Entity Oriented Design, feod.dev) |
| Состояние и логика | **MobX** — по умолчанию вся логика фронтенда (бизнес и UI) живёт в MobX-сторах |
| Роутинг | TanStack Router |
| Формы | React Hook Form |
| UI | shadcn/ui + Tailwind CSS |
| Backend | Node.js + TypeScript + **Fastify** |
| База данных | SQLite + **Drizzle ORM** (схема в TS, миграции через drizzle-kit) |
| Валидация | **Zod** — схемы запросов/ответов; переиспользуются на фронте в RHF |
| Авторизация | email + пароль, bcrypt + JWT (`@fastify/jwt`) |
| Озвучка | Web Speech API (браузерная, бесплатная) |

### 5.1. Принципы фронтенда
- **Вся логика — в MobX-сторах:** и бизнес-логика (SRS-сессия, словарь,
  авторизация), и UI-состояние (фильтры, сортировки, открытые панели).
  React-компоненты тонкие: рендер + вызов действий стора (`observer`-обёртки).
- **Структура — по FEOD:** строгая цепочка импортов `common → modules → pages → app`,
  доступ к модулям только через их публичный API (`index.ts`),
  в `common` — однофайловые сущности без barrel-файлов.
- Формы (вход/регистрация, добавление и редактирование слова) — на React Hook Form.
- Компоненты UI — shadcn/ui (Button, Input, Select, Dialog, Card, Tabs...),
  стилизация — Tailwind CSS.
- Роуты объявляются через TanStack Router; дерево роутов собирается в `app/`,
  маршруты модулей — из самих модулей.

Правила монорепы:
- `@wordforge/shared` — единственный источник правды для контракта API:
  сервер валидирует запросы этими схемами, клиент — формы (RHF + zodResolver)
  и типизирует ответы. Меняется контракт — TS ломает сборку обеих сторон сразу.
- apps не импортируют друг друга; общий код — только через packages.
- `pnpm dev` в корне (через turbo) поднимает клиент и сервер параллельно.

### 5.3. Схема базы данных
```sql
users    (id, email UNIQUE, password_hash, created_at,
          streak, last_study_day)
cards    (id, deck TEXT,            -- words | phrasal | idioms
          en TEXT, ru TEXT, example TEXT,
          cefr TEXT,                -- A1 | A2 | B1 | B2 | C1 | C2
          topic TEXT,               -- еда, путешествия, работа...
          synonyms TEXT,            -- через запятую, может быть пустым
          antonyms TEXT,            -- через запятую, может быть пустым
          owner_id NULL REFERENCES users,   -- NULL = встроенная
          created_at TEXT)
progress (user_id, card_id, level INT DEFAULT 0,
          due_at TEXT, hidden INT DEFAULT 0,
          PRIMARY KEY (user_id, card_id))
```

### 5.4. API (все /api/*, кроме auth — требуют JWT)
```
POST /api/auth/register   {email, password} → {token}
POST /api/auth/login      {email, password} → {token}
GET  /api/cards           словарь с прогрессом пользователя; параметры:
                          ?deck=&cefr=&topic=&status=&search=&sort=&order=
POST /api/cards           добавить свою карточку
PUT  /api/cards/:id       изменить свою / скрыть-показать встроенную
DELETE /api/cards/:id     удалить свою
GET  /api/topics          список категорий с количеством слов
GET  /api/session?deck=&cefr=&topic=&size=15   карточки для сессии (due + новые)
POST /api/review          {card_id, known: bool} → обновить SRS + стрик
GET  /api/stats           {due, learned, streak, byDeck, byCefr}
```

## 6. Нефункциональные требования

- Язык интерфейса: русский
- Адаптивная вёрстка, mobile-first (основной сценарий — телефон)
- Запуск для разработки: `pnpm dev` в корне (Turborepo поднимает клиент и сервер)
- Пароли не хранятся в открытом виде; JWT-секрет — через env с дефолтом для dev

## 7. Фазы

**MVP (фаза 1):** всё из разделов 2–5.

**Фаза 2 (после обкатки):** транскрипция, график активности, достижения,
тёмная тема, экспорт/импорт слов, восстановление пароля,
автоподбор синонимов/антонимов и переводов через словарный API.
