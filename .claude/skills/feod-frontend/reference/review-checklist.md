# Чеклист ревью структуры FEOD

Прогонять при ревью кода, после генерации новых файлов и при рефакторинге.

## 1. Направление импортов

- [ ] Все импорты идут строго вниз: `app → pages → modules → common`?
- [ ] Нет обратных импортов (common импортирует modules; modules импортирует
  pages; что-либо импортирует app)?
- [ ] globals ничего не импортирует и не импортируется в коде приложения?

## 2. Публичные API модулей

- [ ] Чужие модули импортируются ТОЛЬКО через их `index.ts`
  (`@/modules/X`, не `@/modules/X/store/...`)?
- [ ] `index.ts` модуля экспортирует только необходимое (не всё подряд)?
- [ ] Нет глубоких импортов внутренностей чужих модулей?

## 3. Подмодули

- [ ] Нет обращений к подмодулям чужих модулей?
- [ ] Нет обращений «через голову» (к подмодулям своих подмодулей)?
- [ ] Родитель не лезет во внутренности подмодуля мимо его `index.ts`?
- [ ] Вложенность подмодулей ≤ 3 уровней?
- [ ] Приватное ядро сквозного модуля (`_/`) используется только его подмодулями?

## 4. Common тонкий

- [ ] Нет barrel-файлов (`index.ts`) в common, импорты прямые из файлов?
- [ ] Каждая сущность — один файл?
- [ ] Нет бизнес-логики / привязки к фичам?
- [ ] Нет прямых импортов модулей (только IoC)?
- [ ] Сущности, разросшиеся на несколько файлов, вынесены в модули?

## 5. Тонкие pages

- [ ] Страницы — только композиция модулей + состояния loading/error?
- [ ] Бизнес-логика не «протекла» на страницы?
- [ ] Пути файлов соответствуют URL (`[id].tsx`, `[...404].tsx`, `index.tsx`)?
- [ ] Приватные модули страниц (`_name/`) используются только своей страницей?
- [ ] Layout выбирается в роутере, а не внутри страницы?

## 6. App без бизнес-логики

- [ ] В app только: entry, роутер, конфиги, интеграции, layouts?
- [ ] Интеграции — это инициализация внешних сервисов, а не переиспользуемая логика?
- [ ] Конфигурация централизована (env читается только в app)?

## 7. Globals минимален

- [ ] Только типы/полифиллы/shims/манки-патчи?
- [ ] Каждое расширение типов задокументировано (зачем)?
- [ ] Ничего, что требует импорта?

## 8. Кросс-модульные связи

- [ ] Взаимодействие модулей минимизировано?
- [ ] Где возможно — IoC (интерфейс + внедрение из app) вместо прямого импорта?
- [ ] Нет циклических зависимостей между модулями?

## 9. Именование

- [ ] Имена модулей отражают доменную ответственность
  (`UserProfile`, `OrderHistory`), а не технические детали?
- [ ] Нет слишком общих имён (`User`, `Data`, `Utils`) и сокращений?

## 10. Проектные конвенции

- [ ] Соблюдены конвенции стека проекта? Проверить по документации проекта
  (для этого репозитория — `docs/frontend-conventions.md`).

## Обработка нарушений

Нарушение → исправить. Если исправление объективно вредит (редкий случай) —
оставить с комментарием-обоснованием прямо в коде и упомянуть в README модуля.
Молчаливых отступлений не бывает.
