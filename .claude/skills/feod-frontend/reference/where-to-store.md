# Где хранить... (практический справочник)

Философия: понимай логику и правила FEOD, а не зазубривай ответы. Если логика
FEOD соблюдается, несколько вариантов размещения могут быть правомерными.
«Лучшее — враг хорошего»: если соблюдение правила теряет что-то важное,
допустимо отступление — с документированием причин.

## API-запросы к серверу

| Где | Что |
|-----|-----|
| `modules/<Domain>/api/` | функции/клиенты конкретных эндпоинтов домена; DTO и типы ответов — рядом, наружу — через `index.ts` |
| `app/integrations/` | инфраструктура: конфигурация HTTP-клиента, base URL, интерцепторы, авторизация (JWT), retry-логика, SDK |
| `common/utilities/` | только обезличенные утилиты без привязки к домену: обёртка над fetch, парсер ошибок, хелпер query-string |
| `globals/` | API-логика здесь НЕ размещается |

## Layouts

| Где | Что |
|-----|-----|
| `app/layouts/` | **в абсолютном большинстве случаев** — layout это надстройка над приложением, не часть страницы; `routes.ts` тоже здесь |
| `modules/` | допустим модуль layouts; при страницах внутри модулей — приватные layouts для вложенных страниц |
| `common/` | НЕ рекомендуется — связанные сущности разделяются по абстракции, а не по назначению |
| `globals/` | только расширение интерфейсов фреймворка (например, RouteMeta), сами компоненты — нет |

## Локализация (i18n)

| Где | Что |
|-----|-----|
| `app/` | глобальные конфиги i18n со всеми переводами без привязки к модулям |
| `modules/<X>/i18n/` | переводы конкретного модуля — внутри него (изоляция) |
| `common/` | НЕ рекомендуется: переводы — сильно связанные между собой сущности |
| `globals/` | только shims фреймворка i18n, сами переводы — нет |

## Типы

| Где | Что |
|-----|-----|
| `globals/` | типы, доступные без импорта |
| `modules/<X>/types/` | множество логически связанных типов домена |
| `common/types/` | базовые утилитарные типы без бизнес-привязки, один файл |

## UI-библиотека / дизайн-система

- Рекомендуется как модуль (часть домена).
- Нужны компоненты UI-модуля в common → IoC, или отказ от использования
  в common, или задокументированное исключение.
- Простой набор базовых независимых компонентов без полноценной
  дизайн-системы — может жить в `common/ui/`.

## Быстрая шпаргалка

| Что | Куда |
|-----|------|
| HTTP-клиент, интерцепторы, base URL | `app/integrations/http.ts` |
| Запросы эндпоинтов домена + DTO | `modules/<Domain>/api/` |
| Обёртка над fetch без домена | `common/utilities/` |
| Layout | `app/layouts/` |
| Константы маршрутов | `common/constants/routes.ts` |
| Стор фичи (state-менеджер) | `modules/<Feature>/store/` |
| Переиспользуемый хук без бизнес-логики | `common/hooks/` |
| Базовый однофайловый UI-компонент | `common/ui/` |
| env.d.ts, расширения типов | `globals/` |
