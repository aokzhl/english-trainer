# Уровень App — запуск и настройка приложения

## Назначение

App описывает всё, что необходимо для **запуска приложения и его настройки**.
По сути это bootstrap-слой (в FEOD обсуждалось даже переименование в `boot`).
Это отправная точка при изучении кодовой базы: максимум конфигураций и
интеграций при минимуме бизнес-логики.

**Ключевое правило:** app не импортируется никем. Он вершина цепочки.

## Критерии: элемент относится к app, если

- напрямую связан со стартом приложения и его конфигурацией;
- НЕ является переиспользуемой логикой для разных частей проекта;
- это конфигурация или интеграция с внешним сервисом, критическая для работы
  всего приложения.

Если хоть один пункт не выполняется — элементу место в modules или common.

## Типичная структура

```
app/
├── entry.tsx           # точка входа (createRoot, RouterProvider)
├── router.ts           # сборка дерева роутов (TanStack Router)
├── config.ts           # централизованная конфигурация приложения
├── assets/             # глобальные ассеты (favicon, шрифты)
├── integrations/       # инициализация внешних сервисов
│   ├── http.ts         # HTTP-клиент: base URL, JWT-интерцептор, retry
│   └── analytics.ts
├── layouts/            # layouts приложения
│   └── default.tsx
└── ui/                 # части layout'ов, нигде больше не используемые
    ├── Header.tsx
    └── Footer.tsx
```

## Что разрешено в app

- точка входа приложения;
- маршрутизация (сборка роутера);
- интеграции внешних сервисов;
- глобальные layouts;
- централизованные конфиги.

## Что ЗАПРЕЩЕНО в app

- любая бизнес-логика (ей место в modules);
- переиспользуемые компоненты и утилиты (ей место в common или modules).

## Интеграции

Интеграция ≠ переиспользуемая логика. Интеграция — это **конфигурация и
начальная инициализация** для работы с внешним сервисом.

Паттерн: в app определяется конкретная реализация/конфигурация, которая
подставляется в абстрактную сущность модуля (Inversion of Control):

```typescript
// app/integrations/some-service.ts
import { someExternalService } from '@/modules/SomeExternalService'

const config = {
  apiKey: import.meta.env.VITE_SOME_SERVICE_API_KEY,
}

export function initSomeExternalService() {
  someExternalService.init(config)
}
```

Все `init*()` вызываются из `entry.tsx` при старте.

## Конфигурации

Задача — централизация всех настроек приложения в одном месте (`app/config.ts`).
Это упрощает изменения, контроль параметров и отделяет логику от конфигурации.
Значения из env читаются только здесь, дальше передаются явно.

## Layouts

Layouts живут в app, потому что настраивают общий вид приложения и их части
нигде не переиспользуются. Отдельные части layout'ов (Header, Footer) — в
`app/ui/`. Выбор layout'а для страницы — через конфигурацию роутера,
НЕ внутри самих страниц.

## Роутер

- Роутер собирается в `app/router.ts` и подключается в entry.
- Названия/пути маршрутов выносить в `common/constants/routes.ts`:

```typescript
// common/constants/routes.ts
export const ROUTES = {
  HOME: '/',
  DICTIONARY: '/dictionary',
  SESSION: (mode: string) => `/session/${mode}`,
}
```

- Модули МОГУТ экспортировать собственные маршруты, которые app собирает
  в общий роутер — это рекомендуемый способ модульной маршрутизации:

```typescript
// modules/Auth/routes.ts (экспортируется через index.ts модуля)
export const authRoutes = [
  { path: '/auth/login', component: LoginPage },
]
```
